# 运行状态条（Running Activity Bar）设计

> 2026-09-04 · dsh-clearview 阅读页
>
> 需求：原对话页在运行时底部持续显示 `Deep diving... 1 分 20 秒` 告知用户对话流仍在进行；阅读页缺少等价的状态告知，需要设计。

## 1. 目标

对话流运行期间，阅读页提供一个**常驻**的全局状态提示：让用户随时知道「流还在跑、现在跑到哪个阶段、跑了多久」，并顺带补上阅读页缺失的「回到最新」快捷通道。流结束（或进入等待操作）后自动消失/切换，不干扰正常阅读。

## 2. 现状与缺口

- `GroupStatus`（`Reader.tsx`）已能在**每组折叠行内**显示「正在思考/正在输出/正在使用工具/等待你的操作」+ shimmer，但它只跟随组头，用户滚动离开运行组或运行组不在视口时，看不到整体是否在运行。
- 阅读页没有全局、常驻、带计时的运行状态告知。

## 3. 设计决策（逐项确认）

| # | 决策 | 结论 |
|---|------|------|
| 1 | 常驻 or 临时 | **常驻**：运行期固定在阅读页底部（跟随滚动区域之外），完成即消失 |
| 2 | 条上内容 | **阶段文本 + 秒级计时**（「正在思考 · 1 分 20 秒」） |
| 3 | 计时起算 | **阶段各自计时**：从当前阶段起始时刻起算，切换阶段归零重计 |
| 4 | 阶段判定来源 | **独立 `useTurnActivity` hook** 派生「最新活动」，阶段文本复用 GroupStatus 的判定函数（同一份逻辑，避免口径漂移） |
| 5 | 更新节律 | **秒级 `setInterval`**：`now` 每秒更新一次，派生结果（阶段+秒数）不变时不触发重渲染 |
| 6 | 等待操作 | 切换为「等待你的操作」并**清空计时**（与 GroupStatus 文案一致） |
| 7 | 视觉形态 | **直角/极小圆角矩形悬浮条**：4~6px 圆角、毛玻璃浅背景 + 细边框，随内容轻微上浮；**不做胶囊/药丸造型** |
| 8 | 按钮行为 | 条上「回到最新」按钮复用 `scroll.jump()`（清除阅读器内选区/焦点 + 滚动回底部 + 重建跟随），语义一致 |
| 9 | 常驻 vs 打扰 | **内容离开底部时条自动淡出**（低可见度），回到底部时恢复完整可见 |
| 10 | 阶段切换瞬间 | 计时从新阶段起始时间戳重计，不保留累计 |
| 11 | 边界情况 | **仅当存在运行中轮次时显示**；加载历史/会话读取失败/无运行轮次不显示 |

## 4. 行为定义

### 4.1 状态与触发

- **显示条件**：`chat.timeline.turns` 中存在 status='open' 的轮次（含 `pending.length > 0` 时的等待态，但文案不同）。无运行中轮次 → 条整体隐藏。
- **阶段判定**：
  - `snapshot.pending.length > 0` → `等待你的操作`（计时清空）
  - 运行中轮次的最新 assistant-step：
    - 最后 block 为 `reasoning` → `正在思考`
    - 最后 block 为 `text` → `正在输出`
    - 最后 block 为 `tool-call` → `正在使用工具`（正在生成输入时 `正在准备工具输入`）
  - 以上均不满足 → `正在处理`
- 阶段文本复用 `GroupStatus` 已有的判定逻辑（提取为纯函数 `turnActivityOf`，供 `GroupStatus` 与底部条共用）。

### 4.2 计时

- 每个阶段起始时刻取自关键消息的时间戳（思考段 `data.time` / 工具 `callTime`，取稳定差值，不依赖估算）。
- 秒级 `setInterval`（1s）驱动 `now`；`useTurnActivity` 内部对派生结果做引用比较，无变化不重渲染。
- 阶段切换（阶段 key 变化）→ 计时归零重计。**阶段 key** = 阶段判定所依赖的身份组合：运行轮次的 turn 序号 + 最新步骤序号 + 最新 block 的位置/类型（reasoning/text/tool-call 及其 callId）；key 不变则计时持续累计，key 变化（含进入 `等待你的操作`）则该阶段起始时刻重取。

### 4.3 视觉

- 悬浮于阅读页滚动区域底部、视口内固定（`position: sticky` 或随滚动容器定位），与内容留白 ≥16px，不遮挡正文。
- 形态：直角/极小圆角（4~6px）矩形条，毛玻璃（`backdrop-filter: blur()`）浅背景 + 细边框，无阴影或极浅阴影；无胶囊造型。
- 内容：`[阶段] · [N 秒/分 秒]`；等待操作时不显示计时。
- 右侧「回到最新」图标按钮（复用 `scroll.jump`；跳转后条恢复完整状态）。
- 进出场动效 ~200ms 淡入淡出 + 轻微上移；内容离开底部时条淡出至低可见度（透明度下降、不消失），回到底部恢复。全部遵循 `prefers-reduced-motion` 与插件 `[data-motion=off]` 降级。

## 5. 文件结构（实现路径）

```
src/client/
├── turn-activity.ts        # 纯函数 turnActivityOf：给定 chat 快照 → {phase, since}（可单测）
├── use-turn-activity.ts    # hook：订阅 useSession 派生 + 秒级 setInterval + 引用比较
└── Reader.tsx              # 渲染 <ActivityBar>（浮层 + 按钮 + 淡出逻辑，内部复用 scroll.jump）
Reader.module.css           # 新增条样式（矩形毛玻璃条、淡出态、reduced-motion）
```

## 6. 错误处理与边界

- `chat` 为空 / 无 open 轮次 → 条不渲染。
- `pending` 变化（提问/审批）→ 文案切换、计时清空；不应产生「流还在跑」的误报。
- 阶段时间戳缺失/非法 → 计时不显示（仅显示阶段文本），不崩溃。
- 选区/焦点守卫照常生效：点击「回到最新」清除阅读器内选区与焦点（复用 `scroll.jump` 已有逻辑）。

## 7. 测试

- 纯函数 `turnActivityOf`：正常阶段/等待操作/无运行轮次/时间戳缺失。
- 计时派生：阶段切换归零、等待态清空计时、值不变不触发更新（引用比较）。
- 视觉/行为在真实宿主验证：常驻悬浮、离开底部淡出、回到底部恢复、`prefers-reduced-motion`、结束消失。

## 8. 范围外（不做）

- 不增加「加载历史」「会话读取失败」等其它状态的底部提示（已有原生提示）。
- 不做整体运行总时长累计（阶段各自计时即可）。
- 不做胶囊/药丸造型（按用户要求矩形条）。
