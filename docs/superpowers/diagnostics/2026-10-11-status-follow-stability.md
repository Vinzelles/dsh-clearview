# 底部运行指示器抖动修复（0.3.7，已发布应用）

## 根因与处理

高速正文输出会反复增加轮次高度。底部运行指示器跟随正常文档流移动，而外层滚动位置仍在缓动追赶，两者交错造成指示器先向下移动、再向上回弹。浏览器因布局、滚动锚点或范围收缩产生的滚动事件，还会被旧规则当成读者离开底部，错误中止自动跟随。

仅最新轮次的底部运行状态，在自动跟随期间保持在原本抵达底部后的视口位置。位置由轮次的正常流边界、剩余滚动距离和宿主预留空间计算。正文继续使用原来的逐词显现、模糊、扫光及滚动缓动。状态表面匹配宿主背景，阅读根保持透明，不增加卡片。

布局滚动不再自行取消跟随。上滚、选区、显式内容跳转及滚动条主键按下仍暂停；向下返回底部或点击返回最新位置恢复。等待确认时取消状态定位，避免覆盖操作提示；思考标题、等待状态、结束提示和早先轮次不参与底部定位。

独立审查补出了两条原生滚动条路径：轨道上翻没有方向移动事件；拇指拖动可只发出 `pointerdown → scroll → pointerup`，没有 DOM `pointermove`。按下时清除旧的自动写入位置，仅在该显式按下期间使用实际滚动方向判断恢复。拇指下拖与触摸内容上滑的方向相反。

发布前真实旧会话预览补出另一条明确阅读意图：展开已完成轮次的长过程时，布局不再自动中止跟随，导致摘要被拉出视口。阅读根仅捕获整轮摘要按钮的点击，先暂停跟随，再由原组件改变折叠状态。浏览器的键盘激活也产生同一点击事件；普通运行中工具/思考控件不受这条规则影响。修复前第二次收起点击坐标为 -1508px、无法命中；修复后两次点击均为 413.75px 且命中，状态按折叠→展开→折叠变化。对应旧会话验证前后均为 775，未创建会话。

- 原生滚动条轨道上翻 720px：后续增长漂移 0px；拇指实际拖回底部，再增长仍自动跟随，末尾距离 2px。使用独立纯 HTML 滚动条作为输入正向对照；未用脚本赋值模拟这两条读者操作。
